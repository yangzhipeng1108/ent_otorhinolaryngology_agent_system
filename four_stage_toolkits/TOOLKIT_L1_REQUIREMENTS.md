### 扫描检查项目（L1-STREAMLINED级别）

#### 🔴 阻塞性问题（必须修复）
1. **需求文档缺失**: spec/requirements/ 目录是否存在核心需求文档
2. **用户故事不完整**: 主要功能是否有基本的用户故事描述
3. **验收标准缺失**: 核心功能是否有基本的验收标准
4. **术语严重不一致**: 关键业务术语是否明显冲突

#### 🟡 警告问题（L1可忽略）
1. **文档格式不规范**: Front Matter、ID编号等格式问题
2. **需求描述不够详细**: 需求描述可以更加具体
3. **依赖关系不明确**: 功能间的依赖关系描述不清晰

#### 🟢 建议优化（L1跳过）
1. **需求分类可优化**: 需求分类和组织可以进一步优化
2. **用户体验细节**: 用户体验相关的细节可以补充

### L1修复范围（最小可行修复）

#### ✅ 会修复的问题
1. **创建缺失的基础文档结构**
   - 在spec/requirements/创建核心需求文档
   - 补充基本的用户故事模板

2. **修复明显的术语不一致**

4. **避免过度修复**: 不追求完美，确保可用即可

## 📋 4. L1-STREAMLINED关键特征

### L1-STREAMLINED原则
- **输入灵活**: 支持目录和文件作为输入上下文
- **问题优先级**: 只关注🔴阻塞性问题，忽略🟡🟢
- **修复深度**: MVP修复，让需求"基本可用"即可
- **容错性**: 允许不完美，优先速度和可用性

### 防绕过约束
- **禁止智能优化**: 不得添加TOOLKIT外的检查项目
- **禁止扩展功能**: 严格按照定义的req_scan_l1、req_fix_l1执行
- **禁止使用经验**: 不得基于AI内置知识添加建议
- **强制模板**: 必须使用预定义的响应模板格式

### 错误处理
如果遇到无法处理的情况：
1. **立即声明超出L1能力范围**
2. **和用户协商后修复(human-in-the-loop)** - 特别是业务逻辑理解问题
3. **不得强行处理复杂业务规则** - L1专注核心用户故事
4. **记录需求澄清问题供后续改进**
