## 🔧 L2结构化修复方案（PMI基础标准）

### 第1优先级：WBS和进度管理
**修复内容**：
- 定位 GOAL 清单文档（通常对应 `[goal_breakdown]` 占位符）并补齐 GOAL front matter（id/sn/status/source_us/related_sc/related_seq）

- 定义任务依赖关系和关键路径
- 设置项目里程碑和阶段性目标

**修复对象参考**：结合 CRAFT 提供的 GOAL 清单 / WBS / 依赖 / 里程碑 / 进度基线维度，在项目实际命名的文档或目录中补齐内容（常见命名如 `goal_breakdown.*`、`wbs_*`、`milestones_*` 等）。

### 第2优先级：资源和成本管控
**修复内容**：
- 配置资源分配和技能匹配

- 建立进度跟踪和偏差控制

**修复对象示例**：
- 资源分配与负载管理文档（参考项目现有 `resource` / `capacity` 相关文件）

- 资源优化与进度跟踪记录（可为单独文档或章节，遵循 CRAFT 所述维度）

### 第3优先级：风险质量管理

## 📋 4. L2-BALANCED关键特征

### PMI基础标准化
- **结构化管理**：WBS工作分解结构，进度基线控制
- **资源优化**：人力技能匹配，成本预算管理
- **风险控制**：基础风险识别登记，应对策略制定
- **团队协作**：沟通计划体系，绩效跟踪机制

### 与L1/L3差异化
- **L1-STREAMLINED**：基本任务分解（敏捷导向）
- **L2-BALANCED**：PMI基础标准化（结构化管理）
- **L3-RIGOROUS**：PMBOK企业级（审计就绪）

## 工具执行约束

### L2-BALANCED原则
- **标准化平衡**: 结构化管理与灵活性平衡
- **问题优先级**: 🔴阻塞性问题优先，🟡警告问题考虑处理
- **修复深度**: PMI基础标准修复，确保项目管理体系完整
- **质量要求**: 团队协作有效，文档规范化

### 防绕过约束
- **禁止智能优化**: 不得添加TOOLKIT外的检查项目
- **禁止扩展功能**: 严格按照定义的task_scan_l2、task_fix_l2执行
- **禁止使用经验**: 不得基于AI内置知识添加建议
- **强制模板**: 必须使用预定义的响应模板格式

### 错误处理
如果遇到无法处理的情况：
1. **立即声明超出L2标准化能力范围**
2. **和用户协商后修复(human-in-the-loop)** - 特别是PMI方法论选择和资源分配决策
3. **不得强行处理企业级复杂项目治理** - L2专注标准化项目管理
4. **记录项目管理复杂度问题供后续改进** - 重点关注结构化管理效果
