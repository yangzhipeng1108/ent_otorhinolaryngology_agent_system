# 🔧 TOOLKIT_SHARED_IMPLEMENTATION - 实施阶段跨Level共性工具

⚠️ **执行约束**：本文件为 AI Agent 的强制执行指令，所有共享命令必须遵循既定流程，不得以经验臆测替代。

---

## 共性命令调用验证清单

在执行任何共享 `>>实施*` 命令前，AI Agent 必须确认：
- [ ] 用户显式调用了 `>>实施策略总览` / `>>实施测试矩阵` / `>>实施任务拆解` / `>>实施收束写回` 之一
- [ ] 当前上下文处于 IMPLEMENTATION 阶段（Stage-3，TDD 主场）且 Level 与工具包一致
- [ ] 已完整读取本文件及对应 Level 的实施工具包配置
- [ ] 草稿工作区（参考 `CRAFT_SHARED` 中的草稿目录约定，如 `spec/implementation/_draft_<topic>/`）与版本信息（`draft_v{N}.md`）已建立或已同步
- ℹ️ Level 约束与深度由 `SPEC_PRJ_LEVEL`、对应的 `TOOLKIT_L{1|2|3}_IMPLEMENTATION.md` 及 `CONSTRAINT_L{1|2|3}_IMPLEMENTATION.md` 提供，本文件仅定义共享命令。

✅ 满足以上条件后方可执行命令；如参数缺失必须先与用户确认。

---

## 共享命令总览（当前 4 个，持续扩充）

1. **>>实施策略总览** — 汇总实施上下文、TDD 基线、环境基线、风险假设，建立主题草稿的起点。
2. **>>实施测试矩阵** — 设计测试金字塔、覆盖率目标、BDD 场景映射与质量监控策略。
3. **>>实施任务拆解** — 拆解开发/测试任务、粒度控制、依赖映射与迭代节奏。
4. **>>实施收束写回** — 汇总本轮推敲结论、质量门禁状态，并将确认内容写回 `spec/implementation/` 正式资产。

> 若未来扩充命令，保持 `>>实施*` 命名即可；Level 工具包引用“全部 `>>实施*` 命令”即可自动继承能力。

### Level 工具包挂载指引
- 各级别工具包需声明：引用本文件的全部 `>>实施*` 命令，执行前先读取本文件。
- 各工具包可设定缺省 Level；用户传入 level 参数时必须遵从用户指令。
- 新增命令时，需同步更新本文件和相关模板，确保跨 Level 一致。

### 输出骨架
```
## 实施测试矩阵（{LEVEL}）
```

- 引用/刷新需求 AC 与设计阶段产出（接口契约等），确保测试追溯链完整。
- 输出需落地至草稿文件（如 `test_matrix_v{N}_L{level}.md`），并维护 SN / source_vs。
- 识别当前迭代必测 US，并注明缺失测试的风险。

## 草稿管理约定（topic-first + draft_v{N}.md）

- 草稿目录根路径建议：参考 CRAFT 草稿占位符（示例：`spec/implementation/_draft_<topic>/`）
- 版本文件：`draft_v{N}.md`，可按命令生成 `strategy/test/task/summary` 等子文件。
- 推荐结构示例：
  - `draft_dir/strategy_v{N}_L{level}.md`
  - `draft_dir/test_matrix_v{N}_L{level}.md`
  - `draft_dir/task_plan_v{N}_L{level}.md`
  - `draft_dir/summary_v{N}_L{level}.md`
  - `draft_dir/artifacts/coverage_v{N}.csv`（按项目命名）
- Level 信息可写入文件名或 Front Matter，避免额外 Level 子目录导致碎片化。

- 具体标准请参阅对应的 `TOOLKIT_L{1|2|3}_IMPLEMENTATION.md` 与 `CONSTRAINT_L{1|2|3}_IMPLEMENTATION.md`。

## 输入参数建议

- `topic`：主题名称（必填）
- `level`：L1 / L2 / L3（可选；缺省由工具包默认 Level 决定）
- `draft_version`：版本号 N（可选；默认按命令顺序自动 +1）
- `workspace_root`：草稿根路径（可选；未指定时沿用工具包上下文）

---

## 执行约束

- 严禁输出或生成真实代码；仅限实施策略、测试设计、计划内容。
- 不得绕过草稿版控或自行写回正式文档；所有写回通过 `>>实施收束写回` 明确声明。
- 输出需与草稿文件内容保持一致，确保追溯链条完整。
- 若与 Level 工具包要求冲突，以更严格者为准。

---

## 错误处理与协作提醒

遇到以下情况需立即中止并提示用户：
- 主题 / 草稿目录缺失或 Level 不明确
- 需求 / 设计阶段信息缺失导致无法制定 TDD 策略
- 质量门禁数据缺失，无法判断测试现状

> 建议在 Human-in-the-loop 澄清后继续执行；禁止自行假设或创建未经确认的结构。
