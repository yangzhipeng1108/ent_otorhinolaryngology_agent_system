### 扫描检查项目（L1-STREAMLINED级别）

#### 🔴 阻塞性问题（必须修复）
1. **设计文档缺失**: `spec/design/` 目录是否存在核心设计文档
2. **架构图不完整**: 主要组件是否具备基本设计图或描述
3. **技术选型缺失**: 核心技术栈是否有基本选型说明
4. **接口定义不明确**: 关键接口是否具备基本定义

#### 🟡 警告问题（L1可忽略）
1. **文档格式不规范**: 设计文档格式、命名等存在不统一
2. **设计描述不够详细**: 设计细节可以进一步补充
3. **依赖关系不清晰**: 组件间依赖关系描述模糊

#### 🟢 建议优化（L1跳过）
1. **设计模式可优化**: 设计模式使用可以进一步优化
2. **性能考虑细节**: 性能相关的设计细节可以补充

🟡 警告问题：[数量] 个

💡 下一步建议：[基于TOOLKIT文件的建议]
🛠️ 快速修复：使用 >>design_fix_l1 执行自动修复

## 🔧 3. >>design_fix_l1：L1设计一键修复

### 🤖 AI Agent标准响应模板
```

📋 执行design_fix_l1：L1设计一键修复

🔍 修复策略：只修复阻塞性问题（MVP修复原则，支持目录/文件输入）

[严格按TOOLKIT文件内容执行，不添加自己的理解]
```

### L1修复范围（最小可行修复）

#### ✅ 会修复的问题
1. **创建缺失的基础设计文档**
   - 在 `spec/design/` 创建核心设计文档
   - 补充基本的架构图或组件描述
   - 添加基础的技术选型框架

2. **修复明显的架构不一致**
   - 统一关键技术术语（选择使用频率最高的）
   - 批量替换明显错误的组件命名

3. **补充关键缺失信息**
   - 为核心组件添加基本接口定义
   - 补充最基本的技术选型说明

#### ❌ 不会修复的问题（L1级别跳过）
1. **详细格式规范** — L1容忍格式不完美
2. **复杂架构优化** — L1不追求完美架构
3. **高级设计模式分析** — L1保持简单

### 修复执行流程
1. **扫描确认问题**: 基于 >>design_scan_l1 的扫描结果
2. **筛选阻塞性问题**: 只处理 🔴 级别问题  
3. **执行MVP修复**: 使用最简单可行的方案
4. **避免过度修复**: 不追求完美，确保可用即可

## 工具执行约束

### L1-STREAMLINED原则
- **输入灵活**: 支持目录和文件作为输入上下文
- **问题优先级**: 只关注 🔴 阻塞性问题，忽略 🟡🟢
- **修复深度**: MVP修复，让设计 "基本可用" 即可
- **容错性**: 允许不完美，优先速度和可用性

### 防绕过约束
- **禁止智能优化**: 不得添加TOOLKIT外的检查项目
- **禁止扩展功能**: 严格按照定义的 >>design_scan_l1、>>design_fix_l1 执行
- **禁止使用经验**: 不得基于AI内置知识添加建议
- **强制模板**: 必须使用预定义的响应模板格式

### 错误处理
如果遇到无法处理的情况：
1. **立即声明** 超出 L1 能力范围
2. **与用户协商后修复** (human-in-the-loop) — 尤其是技术选型决策
3. **不得强行处理复杂架构设计** — L1保持架构简单
4. **记录技术复杂度问题** 供后续改进
