
### 扫描检查项目（L1-STREAMLINED级别，TDD主场增强）

#### 🔴 阻塞性问题（必须修复）
1. **实施文档缺失**：`spec/implementation/` 是否存在核心实施策略文档
2. **测试框架缺失**：是否配置基础测试框架（如 Jest、pytest 等）
3. **核心功能无测试**：主要业务路径是否缺少最基本的测试用例
4. **测试无法运行**：`npm test` / `python -m pytest` 等基础命令是否可运行
5. **依赖配置错误**：`package.json` / `requirements.txt` 等依赖是否缺失或错误
6. **VS测试资产不完整**：VS是否缺失测试场景、测试数据、外部依赖、执行环境等测试资产

#### 🟡 警告问题（建议关注）
1. **测试覆盖率不足**：覆盖率未达到团队基线（L1 不强制高覆盖）
2. **代码格式不统一**：风格、命名或Lint警告
3. **重构机会明显**：存在重复代码或简单可行的重构点

#### 🟢 建议优化（L1可跳过）
1. **高级测试模式**：BDD、集成、E2E 等扩展测试策略
2. **性能优化**：性能测试与优化建议
3. **架构改进**：深度架构调整或模式优化

### TDD主场快速体检
- **红-绿-重构循环**：是否存在测试先行的证据
- **测试用例质量**：关键测试能否真实验证业务行为
- **失败测试处理**：测试失败时是否提供可诊断信息

### 输出格式
```
✅ 扫描完成：
🔴 阻塞性问题：[数量] 个
🟡 警告问题：[数量] 个  
🟢 建议优化：[数量] 个

📋 问题清单：
1. [阻塞] 问题描述 → 解决方案（1句话）
2. [警告] 问题描述 → 解决方案（1句话）
3. [建议] 问题描述 → 解决方案（1句话）

🧪 TDD状态：当前测试运行与覆盖情况摘要
💡 下一步建议：基于本工具文件输出
🛠️ 快速修复：使用 >>impl_fix_l1 执行自动修复
```

## 🔧 3. >>impl_fix_l1：L1实现一键修复

### 🤖 AI Agent标准响应模板
```

📋 执行impl_fix_l1：L1实现一键修复

🔍 修复策略：聚焦阻塞性问题（MVP原则，支持目录/文件输入）
🧪 TDD主场：确保最小测试循环可运行

[严格按TOOLKIT文件内容执行，不添加自己的理解]
```

### L1修复范围（最小可行 TDD 支撑）

#### ✅ 会修复的问题
1. **创建缺失的实施文档**：在 `spec/implementation/` 补齐核心实施策略、TDD 计划、执行路径
2. **搭建基础测试框架**：增加测试依赖、运行脚本，并生成最小示例测试
3. **修复运行阻塞**：修正无法启动的配置、缺失依赖、语法错误
4. **补足关键测试**：为核心功能编写最基本的单元或集成测试，确保红-绿循环成立
5. **补足VS测试资产清单**：确保每个VS具备测试场景、测试数据、外部依赖、执行环境的完整测试资产

#### ❌ 不会修复的问题（L1级别跳过）
1. **高覆盖率追求**：不强制 80%+ 覆盖
2. **复杂重构**：避免大规模代码调整
3. **高级测试体系**：不覆盖性能、安全、端到端等高级场景

### 修复执行流程
1. **确认问题**：基于 >>impl_scan_l1 的扫描结果
2. **筛选阻塞项**：仅处理 🔴 级问题  
3. **优先测试修复**：优先修复测试框架与关键测试
4. **遵循 MVP 原则**：最小可行修复即可

```
2. 问题2：[问题描述]
   修复前：[现状] 
   修复后：[结果]
   ✅ 修复完成

⚡ 修复摘要：
✅ 已修复：[数量] 个阻塞性问题
⚠️ 跳过：[数量] 个警告问题（L1级别不处理）
```

## 工具执行约束

### L1-STREAMLINED原则
- **输入灵活**：可接受目录或文件作为上下文
- **问题优先级**：聚焦 🔴 阻塞性问题，忽略 🟡/🟢
- **修复深度**：保证 TDD 最小循环可运行即可
- **容错性**：允许不完美，优先速度与可用性

### 防绕过约束
- **禁止智能扩展**：不得擅自增加本工具未定义的检查
- **禁止扩展功能**：严格执行 >>impl_scan_l1、>>impl_fix_l1 定义
- **禁止代码生成**：实现阶段仍聚焦策略和计划，不生成业务代码
- **强制模板**：输出必须遵循既定模板

### 错误处理
若遇到以下情况需立即声明无法处理：
1. **超出 L1 能力范围**（如需复杂重构）
2. **关键信息缺失**（技术栈、测试框架未确认）
3. **质量门禁冲突**（与上游阶段不一致）
4. **需求/设计未敲定**（需先回 Stage 1/2 澄清）
